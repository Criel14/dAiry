# 人生时间轴（Life Timeline）设计文档

## 概述

为 dAiry 新增「人生时间轴」功能。用户只需写日记，AI 自动从日记中提取事件（不限于重大事件，平凡日常中的持续事项也值得记录），以垂直时间轴形式呈现用户的人生总结。目标是：简单、直接、无感——用户不需要做任何额外操作，直观清晰地看到自己今年每个阶段在干什么。

## 设计原则

1. 日记是唯一输入，时间轴数据是纯派生物——丢了可全量重建
2. AI 失败不影响日记保存和主写作流程
3. 增量更新——新增日记只扫描新增部分
4. 所有数据本地 JSON 文件存储，坚果云友好
5. AI 仅通过主进程发起

## 一、数据层

### 1.1 存储结构

一年一个 JSON 文件，路径：`<workspace>/timeline/{YYYY}.json`

```jsonc
{
  "year": 2024,
  "version": 1,
  "generatedAt": "2024-12-31T23:00:00Z",
  "events": [
    {
      "id": "evt_20240315_001",
      "date": "2024-03-15",
      "dateEnd": null,
      "title": "ZenLog GitHub 突破 200 stars",
      "summary": "收到第一个 contributor 的 PR，社区开始活跃起来",
      "detail": "3月14日在 HN 首页展示带来了第一波关注，次日一位 Rust 开发者提交了 PR，修复了 Windows 下的编码问题。这个事件让我第一次感受到开源社区的反馈循环。",
      "diaryDates": ["2024-03-14", "2024-03-15"]
    },
    {
      "id": "evt_20240301_001",
      "date": "2024-03-01",
      "dateEnd": "2024-05-15",
      "title": "高强度学习 Rust",
      "summary": "通过写 ZenLog 练手，每天投入 2 小时以上",
      "detail": "从所有权概念开始，到第三周能写简单的 CLI 工具，再到第五周搞懂生命周期标注。期间 ZenLog 从零到 MVP 到发版，学 Rust 和做项目完全同步推进。",
      "diaryDates": ["2024-03-01", "2024-03-10", "2024-04-02", "2024-05-10"]
    }
  ]
}
```

### 1.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 事件唯一 ID，格式 `evt_{开始日期}_{序号}` |
| `date` | string | 开始日期，`YYYY-MM-DD`。时间点即为事件日期 |
| `dateEnd` | string\|null | 结束日期。`null` = 时间点（未发生过一天）；有值 = 时间段 |
| `title` | string | 事件标题，4-12 字 |
| `summary` | string | 一句话摘要，20-40 字，卡片收起态显示内容 |
| `detail` | string | AI 生成的完整描述，80-200 字，卡片展开态显示 |
| `diaryDates` | string[] | 该事件引用的日记日期列表，用于跳转链接 |

### 1.3 AI 提取规则

**触发时机：** 每次用户写完日记点击「保存」后（或 Ctrl+S），异步触发对当日日记的事件扫描。用户无感知。

**上下文策略：** 与日总结类似，提交给 AI 时附带当日日记原文 + 最近 N 天（取 `config.json` 的 `ai.dailyContextDays`，默认 7 天）的日记摘要，帮助 AI 理解上下文、判断事件起止范围。

**提取规则（写入 prompt）：**

- 事件必须基于日记原文，不能无中生有
- 事件标准：宽泛——既可以是大事件（里程碑、转折、突破），也可以是持续时间较长的平凡日常（如"连续三周加班""每天学英语""重感冒一周"）。核心原则：让用户能直观看出自己在每个阶段主要在做什么
- 标题：4-12 字，简洁有力
- 摘要：20-40 字，说明事件的本质
- 详情：80-200 字，结合日记原文适当扩展
- `dateEnd`：有明确结束日期的时间段才填，否则填 null。对于持续中的事项（如"仍在每天跑步"），dateEnd 填 null 但可在详情中注明「进行中」
- 如果当日日记无明显新事件，返回空数组
- 如果翻看上下文后发现已有事件在延续或结束，更新对应事件的 `dateEnd` 和 `detail`

**增量扫描流程：**

1. 读取当日日记 Markdown + 最近 N 天日记摘要（提供上下文）
2. 读取该年已有的 timeline JSON
3. 调用 AI，给出日记原文 + 上下文摘要 + 已有事件列表（避免重复，同时用于发现需更新的事件） + 提取规则
4. AI 返回新增的事件 + 需更新的已有事件（如 dateEnd 后延或封闭）
5. 合并写入 JSON

**首次全量扫描：** 用户首次使用该功能（或手动点击「重新整理本年度时间轴」）时，按周分批扫描所有历史日记（每周 7 天为一个批次），每批调用一次 AI 提取该周内的事件，所有批次完成后合并写入对应年份 JSON。分批处理进度通过 preload 事件通知渲染进程。

### 1.4 数据体量估算

按每天 200 字日记、每年约 30-50 个事件计算（包含日常时间段事件）：
- 每个事件 ~300-500 字节
- 一年 JSON ~15-30KB
- 十年也只需 ~200-300KB

完全适合坚果云同步。

### 2.2 左侧控制面板：TimelineSidebar

**直接复用 ReportsSidebar 年度模式的年份选择器组件**，不做重复开发。该组件包含：

- **工具栏**：`<<` 图标按钮（上翻 12 年） | 居中年份范围标题（如 `2024 - 2035`） | `>>` 图标按钮（下翻 12 年）
- **3×4 网格**：12 个年份按钮，样式与现有 `picker-cell` 完全一致
  - 选中年份加粗边框 (`picker-cell--selected`)
  - 当前实际年份特殊边框 (`picker-cell--current`)
  - 已有时间轴数据的年份柔和强调背景 (`picker-cell--has-timeline`)
- **「回到本年」按钮**

在此基础上额外添加：

- **「重新整理本年度时间轴」按钮**（位于选择器下方）：
  - 点击后弹出确认对话框，提示："AI 将完整扫描本年所有日记重新生成时间轴，预计消耗较多 token，确定继续？"
  - 用户确认后主进程按周分批调用 AI（每周 7 天日记为一个批次），逐批提取事件
  - 所有批次完成后合并写入 JSON，并刷新界面
  - 重建过程中按钮显示加载态，不可重复点击

### 2.3 右侧时间轴

纯时间轴展示区域，无控制面板干扰。

- 按月分组，每月有标题行（如 `═══ 7月 ═══`）
- 月份之间按自然顺序排列，1月到12月
- 月份内的空间按当月天数比例分配

### 2.4 时间标记

- **时间点**（单日事件）：圆点 `●`，位于竖线上
- **时间段**（跨日事件）：圆角矩形段，起点对齐 `date`，终点对齐 `dateEnd`
  - 段的高度 = 当月高度 × (该段在当月内占的天数 / 当月总天数)
  - 跨月时间段：在起始月显示完整起点，沿竖线向下延伸到结束月

### 2.5 重叠偏移 + 颜色区分

当一个月内多个事件的时间范围有重叠时，采用**偏移 + 颜色**双层区分：

**偏移规则：**
1. 按事件持续时间降序排列
2. 第 1 个（最大）= 偏移 0，直接贴在时间轴竖线上
3. 第 2 个 = 偏移 1 身位
4. 第 n 个 = 偏移 n-1 身位
5. 每个身位宽度 = 28px（含间距）

**颜色规则：**
- 每个事件分配一个低饱和度颜色，仅用于区分不同事件，颜色不携带任何语义
- 颜色数量视需要而定（通常不需要超过 8 种）
- 颜色选择算法：在 HSV 色轮上均分色相（H），使用较低的饱和度（S 约 25-35%），明度（V）跟随主题模式（浅色模式偏高、深色模式偏低）
- 颜色作为 CSS 变量定义在 token 中，供主题文件覆盖深色模式值

示例色板（8色）：
```
#A8C5D6  #B8D0A8  #D6C5A8  #D6A8C1
#A8D4D6  #C5A8D6  #D6D0A8  #A8B5D6
```

### 2.6 事件卡片

**收起态：**
- 高度约 36-40px
- 显示：时间标记（点/段，带事件颜色） → 连接线 → 卡片标题（1行）
- 右下角：小图标按钮，点击跳转到对应日记

**展开态（点击卡片触发）：**
- 显示完整 `detail` 内容
- 底部列出 `diaryDates` 作为可点击的日记快捷链接
- 再次点击或点其他位置收起

### 2.7 日记跳转

点击卡片右下角的日记链接按钮：
- 如果只有一个 `diaryDates`，直接跳转到该日记
- 如果有多个，弹出小菜单列出所有日期，点击跳转
- 跳转行为：切换到日记面板 + 加载对应日期的日记

### 2.8 主题适配

- 时间轴竖线、圆点使用主题 token（`--color-border` 系列）
- 事件颜色段和点的颜色使用新增的事件颜色 token
- 卡片使用现有报告卡片的 token（`--color-glass-ivory-72`）
- 深色/浅色模式下事件颜色不同（在 `tokens/dark.css` 中覆盖）

## 三、导航变更

### 3.1 问题

当前右侧面板只有 3 个按钮（写作、报告、设置），增加「人生时间轴」后需要调整。

### 3.2 可选方案

**A) 改为 2×2 网格布局：**
```
┌────────┬────────┐
│ 写作   │ 时间轴 │
├────────┼────────┤
│ 报告   │ 设置   │
└────────┴────────┘
```
简单、空间利用好。

**B) 改为左侧垂直标签栏（类似 VS Code 侧栏图标）：**
```
┌──┐
│📝│ ← 写作
│🕐│ ← 时间轴
│📊│ ← 报告
│⚙│ ← 设置
└──┘
```
节省水平空间，但改动较大。

**推荐方案 A（2×2 网格）**，改动最小，视觉清晰，后续还可扩展为 2×3 等。

### 3.3 入口位置

时间轴作为一个独立的 RightPanel：`'timeline'`，与 `'journal'` / `'reports'` / `'settings'` 平级。

## 四、实现范围

### 4.1 主进程新增

| 模块 | 路径 | 职责 |
|------|------|------|
| timeline service | `electron/main/timeline/service.ts` | 时间轴 JSON 读写、增量/全量事件提取协调 |
| timeline AI | `electron/main/timeline/ai.ts` | 调用 AI 从日记提取事件，prompt 管理 |
| AI prompt | `electron/main/ai/prompts/timeline-extract.md` | 事件提取的系统提示词 |

### 4.2 Preload 新增 API

| API | 说明 |
|-----|------|
| `getTimeline(year)` | 获取某年时间轴数据 |
| `regenerateTimeline(year)` | 手动触发某年时间轴重建 |

### 4.3 渲染进程新增

| 组件 | 路径 | 职责 |
|------|------|------|
| TimelinePage | `src/components/timeline/TimelinePage.vue` | 时间轴页面总控，左右分栏 |
| TimelineSidebar | `src/components/timeline/TimelineSidebar.vue` | 左侧面板：复用 ReportsSidebar 的年份选择器 + 重新整理按钮 + 确认弹窗 |
| TimelineView | `src/components/timeline/TimelineView.vue` | 右侧垂直时间轴渲染（月分隔、竖线、点、段、颜色分配、重叠偏移） |
| TimelineCard | `src/components/timeline/TimelineCard.vue` | 事件卡片（收起/展开） |

说明：年份选择器的网格、工具栏、翻页逻辑直接从 ReportsSidebar 的年度选择器抽取为共享组件，避免重复代码。

### 4.4 导航变更

- `RightPanel` 类型新增 `'timeline'`
- 导航按钮从 3 个横向排列改为 2×2 网格布局
- AppShell 相关状态和 composable 更新

### 4.5 主题新增

- `src/shared/theme/tokens/content.css` 新增事件颜色 token（8 个），在 HSV 色轮上均匀分布
- `src/shared/theme/tokens/dark.css` 覆盖深色模式下的事件颜色值

### 4.6 类型定义

`src/types/timeline.ts`: TimelineEvent、TimelineYearData、等。
